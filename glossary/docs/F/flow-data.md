# What is flow data?

Flow data is the structured metadata that network devices generate for every observed traffic conversation. Each record captures the essentials of a conversation: the source and destination IP addresses and ports, the protocol, the start and end time, and the byte and packet counts exchanged. Flow data does not contain packet payloads. It is a summary of what happened on the network, not a recording of the content. That distinction defines both its limits and its value: flow data is lightweight enough to collect across an entire network and retain for weeks, making it the primary source for traffic analysis, security detection, and compliance audit at any scale.

---

## What flow data contains

At its most basic, a flow record contains the 5-tuple, timestamps, and counters. In NetFlow v9 and IPFIX, the record format is defined by a template that the exporter sends to the collector. This allows extended fields to be included alongside the standard fields: ingress and egress interface identifiers, BGP origin and peer AS numbers, DSCP and ToS markings, VLAN IDs, and application-layer identifiers where the device supports deep packet inspection.

What fields arrive at the collector depends entirely on the exporter. Two routers from different vendors may both export IPFIX but include different sets of fields. A collector that expects a field not present in a given template will receive no value for it, which affects any analysis or alerting that depends on that field.

---

## Flow data in network operations

NOC teams use flow data as the primary source for bandwidth trending, top talker identification, and interface utilization analysis. Because every router and switch in a network can export flow records natively, flow data provides network-wide coverage from existing infrastructure.

SOC analysts use flow data to detect threats that do not require payload inspection: connections to known malicious destinations, internal hosts scanning the network, large unexpected data transfers, and long-duration outbound sessions. Because flow data is retained for weeks, it also supports retrospective investigation when a new indicator of compromise is identified after the fact.

ISPs use flow data to meet regulatory data retention obligations, drive traffic engineering decisions, and analyze per-AS and per-prefix traffic for peering and capacity management.

## Flow data vs packet data

| Dimension | Flow data | Packet data |
|---|---|---|
| What it contains | Conversation metadata: 5-tuple, counts, timestamps | Full packet including headers and payload |
| Payload visibility | None | Full, subject to encryption |
| Storage per day at 10 Gbps | A few gigabytes | Tens of terabytes |
| Retention period | Weeks to months | Hours to days at full fidelity |
| Collection source | Any router or switch with NetFlow or sFlow | Dedicated tap or SPAN port with capture probe |
| Best fit | Detection, trending, compliance, scoping | Investigation, confirmation, artifact recovery |

Flow data and packet data answer different questions. Flow data tells you what connections occurred and how much data moved. Packet data tells you what was exchanged. Most mature deployments maintain both: flow data for breadth and retention, packet data for depth at specific observation points.

## How Trisul handles flow data

Trisul ingests flow data from NetFlow v1, v5, v9, Flexible NetFlow, IPFIX, and all sFlow versions, storing every record without rollup or summarization. All routers and interfaces are auto-discovered when the first records arrive. The full resolution of the flow database is available for historical queries at any point within the retention window, whether the query runs minutes or weeks after the traffic occurred.

For links where device-level flow export is unavailable or produces sampled data, Trisul can generate flow records directly from raw packet capture, producing complete unsampled flow data independently of the network device. Flow Taggers attach searchable labels to flow records at ingestion, and Explore Flows provides a query interface for retrieving and pivoting through flow data by any combination of IP, port, protocol, time range, or tag. Full documentation is at https://docs.trisul.org/docs/ug/flow/.

## Frequently asked questions

### What fields does flow data contain?

A basic flow record contains the 5-tuple (source IP, destination IP, source port, destination port, protocol), start and end timestamps, byte and packet counts, and TCP flags. Extended formats like IPFIX carry additional fields depending on the exporter: ingress and egress interface, BGP AS numbers, VLAN IDs, DSCP markings, MPLS labels, and application identifiers. What is present in any given record depends on the exporter platform and its configured template.

### How is flow data different from log data?

Flow data is generated automatically by network devices for every observed conversation, without requiring any configuration on the communicating endpoints. Log data is generated by applications and systems and describes events at the application layer. Flow data covers all network activity regardless of whether any application logs it; logs describe what an application chose to record. For detecting unauthorized or unexpected network activity, flow data is more complete because it is not dependent on endpoint cooperation.

### Can flow data be used for compliance and audit purposes?

Yes. Flow data is the standard audit trail for network-level activity in regulated environments. In India, TRAI and DoT regulations for Internet Service Providers require retention of IP-level connection records, which flow data satisfies. Flow records document which IP addresses communicated, the protocols used, timestamps, and data volumes, providing the connection-level audit trail required by lawful intercept and data retention frameworks without storing payload content.

### How long should flow data be retained?

Retention requirements vary by use case and jurisdiction. For security operations, 30 to 90 days is a common baseline, chosen to exceed the typical dwell time of a threat actor before discovery. For regulatory compliance in India, DoT guidelines specify minimum retention periods for IP flow records. For capacity planning and trending, shorter retention of 7 to 30 days is usually sufficient. Flow data is compact enough that extending retention beyond these minimums is often practical without significant infrastructure cost.
